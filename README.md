# Тренд-радар скиллов Claude Code

Двадцать самых устанавливаемых скиллов Claude Code для разработки и
видеопродакшена. Обновляется автоматически каждый вторник.

**Страница:** https://alexnordoff-byte.github.io/claude-skills-trend-radar/

## Как это работает

Каждый вторник в 09:00 UTC (12:00 МСК) GitHub Actions запускает
`.github/workflows/weekly-radar.yml`: собирает живые звёзды
(`scripts/fetch-stars.js`), пересобирает страницу (`build.js`) и коммитит.
Пуш и есть публикация — GitHub Pages обновляется за минуту. Ни агента, ни
внешних сервисов в цепочке нет.

Запустить вручную: вкладка **Actions** → *Weekly trend radar* → **Run
workflow**. Локально — `node scripts/fetch-stars.js && node build.js`.

## Чем меряем, и почему так

Было: установки с `claudemarketplaces.com` — честная метрика использования.
**Ресурс перестал обновлять данные 21 августа 2026**, и пять недель подряд
радар публиковал замороженные числа, уверенно рисуя «без изменений». Он
умел замечать движение, но не умел замечать обрыв.

Стало:

- **Разработка** — живые звёзды родительского репозитория с GitHub, плюс
  прирост за неделю. Звёзды принадлежат репозиторию, а не скиллу, поэтому
  в монорепо у всех скиллов число одинаковое — отсюда лимит два скилла на
  репозиторий.
- **Видео** — прежние установки, помеченные на странице как замороженные.
  Звёздами видео не ранжируется: у `runcomfy-com/skills` 12 звёзд при
  400 000 установок. Дорожку держим на старых данных, пока не появится
  живой источник.
- **Сторож свежести** — если дата сбора не сегодняшняя или источник
  устарел, `build.js` пишет об этом прямо на странице. Молча стухнуть
  больше нельзя.

## Структура

| Файл | Что это |
|---|---|
| `index.html` | Страница, её отдаёт GitHub Pages. **Генерируется, руками не править** |
| `template.html` | Шаблон страницы — вёрстка и стили |
| `build.js` | Сборщик: данные + шаблон → `index.html` + снимок в историю |
| `data/skills.json` | Курируемый список скиллов с русскими описаниями |
| `data/stars.json` | Звёзды с GitHub и дата сбора |
| `data/history.json` | Снимки по неделям, до восьми последних |
| `scripts/fetch-stars.js` | Сбор живых звёзд с GitHub → `data/stars.json` |
| `scripts/discover.js` | Разведка новичков: кто поднялся выше нижней границы доски. Только печатает, ничего не меняет |
| `.github/workflows/weekly-radar.yml` | Еженедельный запуск, вторник 09:00 UTC |
| `prompts/weekly-trend-radar.md` | Когда и как курировать список скиллов (руками, изредка) |
| `docs/superpowers/` | Проектное решение и план |

История замеров живёт в git: каждую неделю — отдельный коммит. Даже если
страница будет затёрта, любой прошлый срез восстанавливается из истории.

## Эксплуатация

Прогоны и их логи — вкладка **Actions** в репозитории. Там же кнопка **Run
workflow** для запуска вне расписания.

Если недельный прогон упал — скорее всего у какого-то отслеживаемого
репозитория сменилось имя или он удалён. `fetch-stars.js` в этом случае
падает намеренно, вместо того чтобы записать неполный `stars.json` и молча
потерять строки. Поправь `data/skills.json`.

**Красный прогон лучше зелёной лжи.** Этот радар пять недель подряд
показывал замороженные числа как свежие, потому что никто не проверял
источник. Теперь две защиты: скрипт падает, если не смог собрать данные, а
`build.js` пишет прямо на странице, если дата сбора не сегодняшняя.
