# Тренд-радар скиллов Claude Code

Двадцать самых устанавливаемых скиллов Claude Code для разработки и
видеопродакшена. Обновляется автоматически каждый вторник.

**Страница:** https://alexnordoff-byte.github.io/claude-skills-trend-radar/

## Как это работает

Раз в неделю облачный агент Claude Code обновляет `data/stars.json` живыми
звёздами с GitHub, при необходимости правит список скиллов, запускает
`node build.js` и коммитит. Пуш и есть публикация — GitHub Pages
пересобирает страницу за минуту. Вёрстку агент не трогает: `index.html`
генерируется скриптом.

## Чем меряем, и почему так

Было: установки с `claudemarketplaces.com` — честная метрика использования.
**Ресурс перестал обновлять данные 21 августа 2026**, и пять недель подряд
радар публиковал замороженные числа, уверенно рисуя «без изменений». Он
умел замечать движение, но не умел замечать обрыв.

Стало:

- **Разработка** — живые звёзды родительского репозитория с GitHub, плюс
  прирост за неделю. Звёзды принадлежат репозиторию, а не скиллу, поэтому
  в монорепо у всех скиллов число одинаковое — отсюда лимит два скилла на
  репозиторий.
- **Видео** — прежние установки, помеченные на странице как замороженные.
  Звёздами видео не ранжируется: у `runcomfy-com/skills` 12 звёзд при
  400 000 установок. Дорожку держим на старых данных, пока не появится
  живой источник.
- **Сторож свежести** — если дата сбора не сегодняшняя или источник
  устарел, `build.js` пишет об этом прямо на странице. Молча стухнуть
  больше нельзя.

## Структура

| Файл | Что это |
|---|---|
| `index.html` | Страница, её отдаёт GitHub Pages. **Генерируется, руками не править** |
| `template.html` | Шаблон страницы — вёрстка и стили |
| `build.js` | Сборщик: данные + шаблон → `index.html` + снимок в историю |
| `data/skills.json` | Курируемый список скиллов с русскими описаниями |
| `data/stars.json` | Звёзды с GitHub и дата сбора |
| `data/history.json` | Снимки по неделям, до восьми последних |
| `prompts/weekly-trend-radar.md` | Инструкция агента — то, что реально выполняется |
| `docs/superpowers/` | Проектное решение и план |

Собрать страницу локально: `node build.js` (без зависимостей, нужен только
Node).

История замеров живёт в git: каждый вторник — отдельный коммит. Даже если
страница будет затёрта, любой прошлый срез восстанавливается из истории.

## Эксплуатация

Расписание: вторник, 09:00 UTC (12:00 МСК). ID рутины
`trig_012LbsQmuACNR5KEs6wc53iU`.

```
RemoteTrigger action:"list_runs"   trigger_id:"trig_012LbsQmuACNR5KEs6wc53iU"
RemoteTrigger action:"get_run_log" session_id:"<id из list_runs>"
RemoteTrigger action:"run"         trigger_id:"trig_012LbsQmuACNR5KEs6wc53iU"
```

**Доступ в сеть.** Рутина работает в отдельном облачном окружении с
уровнем **Custom**. Custom не дополняет базовый список доменов, а
**заменяет** его целиком — убрав любой из нужных, ломаешь прогон.
Разрешены должны быть как минимум:

```
claudemarketplaces.com
github.com
api.github.com
```

**Зелёная галочка у прогона не значит, что данные обновились.** Если
источник недоступен, агент по инструкции останавливается и ничего не
коммитит — для системы это успешное завершение. Смотри дату в подвале
страницы или последний коммит.

Копия промпта в репозитории — документация; выполняется та, что сохранена
в самой рутине. Менять нужно обе.
